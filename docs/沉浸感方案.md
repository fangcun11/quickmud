# 侠客行 · 文案与沉浸感升级方案

> 来源：北大侠客行实机观摩（见 `pkuxkx-观摩报告.md` 与 `tools/play_record.txt`）。
> 目标：把北侠"人情味 + 世界可信度"的打法移植到侠客行单机版，全部可落在现有
> 引擎（7 通道输出 / rich 标注 / quest / RoomEvent / AtmosphereSystem）之上。

---

## 一、从北侠提炼的四条设计原则

1. **拒绝也是文案**：超时是"下次想好再来吧"，送客是一首 ASCII 送别诗，限流是
   "希望他日江湖再见"。**系统 Every 拒绝/失败/边界情况都必须有叙事出口**，不允许
   出现纯系统报错裸奔。
2. **资源归零写进身体**：食物 0 不是数字变红，而是"你渴得眼冒金星，全身无力"。
   数值变化必须伴随一层身体/感官反馈。
3. **物品与世界状态诚实**：喝空的葫芦照样摆在地上（"一滴也不剩"），玩家名字旁挂
   `<断线二分钟>`。世界不隐藏状态，可信度来自诚实。
4. **人味是设计出来的**：MOTD 署名感言、攻略署名、挂机双簧——单机版用预写内容池
   + NPC 作息模拟"活的江湖"。

## 二、文案规范（写作层，写进内容层 checklist）

### 2.1 语气基准
- 书面武侠腔，但句子短；同一段落不超过两层从句。
- 系统播报一律**第三人称世界视角**（"东方的天空渐渐的发白了"），玩家动作用第二人称
  （"你捡起一枚野果"），NPC 动作带名号（"「野狼」全力出手"）——三种视角不混用。
- 不用网络语、不用感叹号堆砌；幽默靠具体细节（"男性玩家请勿 kiss 李莫愁，后果自负"）。

### 2.2 句式库（每类至少 3 条轮换，禁止单句永久复读）
| 类别 | 现状 | 升级 |
|---|---|---|
| 时辰/天气行 | 单一模板 | 每时辰 × 天气 ≥3 条文学化文案轮换（对标「高秋」） |
| 死亡 | "惨嚎一声，轰然倒地" | 保持，另加尸体/遗物的一句环境收尾 |
| 资源归零 | 无 | 饥/渴/力竭各 2-3 条身体反馈句，随机取用 |
| 移动播报 | "从南面走了进来" | 补一组带姿态的进出场（"一路小跑""踩着落叶"） |
| 踢线/重连 | 无 | 重连叙事："你拍了拍身上的尘土，回到了青石街。" |

### 2.3 拒绝的艺术（错误文案重写清单）
| 场景 | 现文案 | 改为 |
|---|---|---|
| 无效命令 | 我不明白你的意思。 | 你想做什么？江湖没有这条路。——附最近似命令 |
| 打不存在的目标 | 这里没有「野狼」。 | 这里没有「野狼」的踪影。（战斗中：你的对手已不在眼前，你收回了攻势。） |
| 银不够 | 碎银不够——「铁剑」要 15 碎银。 | 你摸了摸钱袋——还差 5 碎银。「铁剑」的价钱挂在那儿呢。 |
| 拿不动 | 你拿不动「石像」。 | 石像纹丝不动——那不是你能拿走的东西。 |
| 走不通 | （按现状） | 那边没有路。（略图开着时：墙就是墙。） |

## 三、沉浸感系统（工程层，8 个可落地机制）

### M1 环境行文案池（改造 AtmosphereSystem）
- 现状：时辰+天气单模板一行。
- 方案：`文案池[时辰][天气] = string[]`，确定性轮换（按房间 id+tick 哈希取，保
  可重放）；重点房间（客栈/山神庙/狼林）写**房间专属**环境句。
- 验收：同一房间 12 时辰走一圈，无重复文案。

### M2 look 明示交互点
- 现状：房间块只列物品/活体。
- 方案：Description 增加 `details: {关键词: 描述}`（小溪、木牌、坟……），房间块追加
  一行"你可以看看(look)：river，path"；`look <关键词>` 返回对应短文（内容层纯数据，
  LookCommand 扩展解析）。
- 验收：未明谷式的"藏在描述里的东西"能被看到并查到。

### M3 资源身体反馈
- 现状：ConsumableSystem 只报数字。
- 方案：Health/Energy 低于阈值时由 vitals 层发一次性身体句（饿了/渴了/内力枯竭，
  各 2-3 条轮换）；战斗中已有伤势警示，补"归零前奏"档。
- 验收：吃光食物后再饥饿，出现身体句而非数字。

### M4 物品状态诚实
- 现状：物品只有"在/不在"。
- 方案：Consumable 增加 `used: 剩余次数`；喝空的仍留在地上（名称不变，look 时带
  "已经空了"）；RoomBlock 对空容器加尾注。
- 验收：喝空葫芦摆地上，look 看得出、喝不动、且回收价为零。

### M5 前辈留言（对标 MOTD）
- 现状：无。
- 方案：房间可选 `留言池`（每条带署名 NPC），进房低概率（确定性哈希）展示一条，
  style=gray 斜体 + 署名红字；山神庙/客栈/武馆优先写 10 条。
- 验收：同一房间多次进出按哈希稳定轮换，可重放。

### M6 "你现在可以"引导面板（对标 jobquery）
- 现状：任务命令只列任务。
- 方案：新增 `建议` 命令（或任务命令尾附），按状态给 1-3 条**命令级**提示：
  经验够学新武功 → "去找铁匠学「基础剑法」"；有可交任务 → "向铁匠交差"；
  饥饿 → "杂货铺有馒头（2 碎银）"。规则纯数据驱动（阈值表）。
- 验收：任何时刻敲它，都有至少一条可执行建议。

### M7 helpme 问答攻略库（对标大高手）
- 方案：`helpme ask 野狼` → 预写条目（出没地/弱点/掉落/提醒），署名虚构前辈；
  无条目时回答"这位前辈也说不清……"。数据即 content 层 dict。
- 验收：≥5 个条目（野狼/铁匠/山神庙/金创药/判师），未命中文案友好。

### M8 异常状态叙事出口（对标 VOID）
- 场景：死亡已有客栈重生；补两类——
  - 卡地图/无环境：系统移到客栈并给一句解释（"一阵天旋地转，你发现自己站在悦来客栈"）；
  - 断线重连：web 客户端重连后展示"你离开的这一阵子……"摘要（offline_log 思路）。
- 验收：人为制造无环境，玩家收到叙事而非卡死。

### M9 闲聊频道的"人味"（可选，单机模拟）
- 方案：AmbienceSystem 低频发 NPC/虚构玩家闲聊条（池子 20+ 条，含双簧对话对），
  走 dialogue 通道；与夜嚎同类，纯氛围不影响状态。
- 验收：跨时辰偶发、确定性、不与重要播报抢行。

## 四、落地批次

| 批次 | 内容 | 改动面 | 规模 |
|---|---|---|---|
| B1 文案规范落地 | 2.3 错误文案重写 + 2.2 句式库（时辰/天气/归零/移动） | prefabs/侠客行文案层 | 小 |
| B2 状态可见 | hp 面板对齐北侠（十项一屏）+ M3 身体反馈 | 侠客行 StatusCommand + vitals | 中 |
| B3 引导 | M6 建议面板 + M7 helpme | prefabs 命令 + 侠客行数据 | 中 |
| B4 世界质感 | M1 文案池 + M2 look 明示 + M5 前辈留言 + M4 物品状态 | prefabs room/behavior + 内容 | 中大 |
| B5 体验收尾 | M8 叙事出口 + M9 闲聊 + 重连叙事 | engine/web/侠客行 | 小 |

每批独立可验收、可回退；B1 建议最先做（纯文案、零风险、观感提升最大）。

## 五、对照示例（改写前后）

改前：
```
> buy 铁剑
碎银不够——「铁剑」要 15 碎银。
```
改后：
```
> buy 铁剑
你摸了摸钱袋——还差 5 碎银。「铁剑」的价钱挂在那儿呢。
（武馆那边好像在收学徒，听说管饭。——去问问？）
```
（第二行即 M6 的语境建议，仅在高价值场景附带。）

改前：
```
时值酉时，天色晴朗。
```
改后（文案池轮换示例）：
```
「高秋」: 暮色四合，青石街上家家点起了灯，饭香混着铁匠铺的炉火气。
```
